# `talos/manifests` - Per-Node Configuration Manifests

This directory contains **Talos manifests** that are appended to the machine configuration for each node. Manifests provide node-specific configuration such as network setup via LinkConfig resources.

## Purpose

While Terraform generates base machine configurations in `../gen/`, manifests allow you to:
- Define per-node network configuration using LinkConfig resources
- Override specific configuration sections per node
- Add node-specific settings after configuration generation
- Apply additional Talos configuration objects without modifying the base machine configuration

## Structure

```
manifests/
├── README.md (this file)
├── <node-name>/
│   ├── linkconfig.yaml (network configuration)
│   └── ... (other manifests)
└── <another-node>/
    ├── linkconfig.yaml
    └── ...
```

Each subdirectory is named after a node and contains YAML manifest files that extend the base configuration.

**Example structure for workers:**
```
manifests/
├── talos-worker-trusted-1/
│   └── linkconfig.yaml
├── talos-worker-dmz-1/
│   └── linkconfig.yaml
├── talos-worker-untrusted-1/
│   └── linkconfig.yaml
└── talos-worker-monitoring-1/
    └── linkconfig.yaml
```

## Manifest Format

Each manifest file contains one or more Talos API objects in YAML format, separated by `---`.

## LinkConfig Manifests for Network Isolation

LinkConfig resources define network interface configuration for isolated worker nodes.

Each worker node has a `linkconfig.yaml` containing:
- **LinkConfig**: Defines eth0 interface with static IP and routes
- **ResolverConfig**: DNS server configuration

### Example: DMZ Worker LinkConfig

**File:** `talos-worker-dmz-1/linkconfig.yaml`

```yaml
apiVersion: net.talos.dev/v1alpha1
kind: LinkConfig
metadata:
  name: eth0
spec:
  name: eth0
  up: true
  addresses:
    - address: 10.10.30.21/24
  routes:
    - destination: 0.0.0.0/0
      gateway: 10.10.30.1
    - destination: 192.168.123.0/24
      gateway: 10.10.30.1
---
apiVersion: net.talos.dev/v1alpha1
kind: ResolverConfig
metadata:
  name: resolvers
spec:
  servers:
    - 8.8.8.8
    - 1.1.1.1
```

**LinkConfig spec fields**:
- `name`: Interface name (eth0)
- `up`: Bring the interface up on boot
- `addresses`: Static IP addresses (CIDR notation)
- `routes`: Static routes with destination and gateway

### Network Isolation via Static Routes

This LinkConfig approach enables network isolation:

1. **Worker attaches only to its workload network** (eth0 on vmbr2 for DMZ)
2. **Default route** directs external traffic through the workload gateway
3. **Control plane route** (192.168.123.0/24) reaches the control plane through the Proxmox host
4. **Proxmox host routing** forwards traffic between bridges, enabling this scheme

## Manifest Format

Each manifest file contains one or more Talos API objects in YAML format, separated by `---`.

**Example manifest:**
```yaml
apiVersion: v1alpha1
kind: DHCPv4Config
name: ens18
---
apiVersion: v1alpha1
kind: HostnameConfig
hostname: talos-controlplane-1
```

### Supported Objects

Common Talos manifest objects:
- `NetworkConfig` - Network interface configuration
- `DHCPv4Config` - Enable DHCP on an interface
- `DHCPv6Config` - Enable DHCPv6 on an interface
- `HostnameConfig` - Set node hostname
- `StaticConfig` - Static IP configuration
- And more from the [Talos API](https://www.talos.dev/latest/reference/configuration/)

## How It Works

### Generation Process

1. Terraform reads files from `manifests/<node-name>/*.yaml`
2. Files are concatenated and appended to the base machine config
3. Final config is saved to `../gen/<node-name>.yaml`

### Configuration Merging

The final machine configuration is composed of:
```
Base Config (generated by Terraform)
  ↓
+ Node-Specific Manifests (from this directory)
  ↓
= Final Machine Config (in ../gen/)
```

Manifests are appended as additional API objects, allowing them to override or extend base configuration.

## Usage Examples

### Example 1: Network Configuration Override

**File: `manifests/talos-controlplane-1/networking.yaml`**
```yaml
apiVersion: v1alpha1
kind: NetworkConfig
interfaces:
  - interface: eth0
    dhcp: true
  - interface: eth1
    static:
      address: 10.0.1.10/24
      gateway: 10.0.1.1
```

### Example 2: Multiple Manifests

**File: `manifests/talos-cp-prod/hostname.yaml`**
```yaml
apiVersion: v1alpha1
kind: HostnameConfig
hostname: talos-cp-prod
```

**File: `manifests/talos-cp-prod/kernel-params.yaml`**
```yaml
apiVersion: v1alpha1
kind: KernelConfig
kernel_parameters:
  - net.core.somaxconn=4096
  - net.ipv4.ip_local_port_range=1024 65535
```

Both files will be concatenated and applied to the node.

### Example 3: Empty/No Manifests

If a node has no manifests directory, only the base configuration is used:
```
manifests/
├── talos-controlplane-1/
│   └── networking.yaml
└── talos-controlplane-2/
    # No files - uses only base config
```

## Editing Manifests

### Add or Modify a Manifest

1. Create or edit a YAML file in the appropriate node directory:
   ```bash
   mkdir -p manifests/talos-controlplane-1
   vim manifests/talos-controlplane-1/custom-settings.yaml
   ```

2. Regenerate the machine configuration:
   ```bash
   cd ../..  # Go back to terraform directory
   terraform apply
   ```

3. Verify the manifest is included in the generated config:
   ```bash
   cat gen/talos-controlplane-1.yaml | grep -A5 "your-manifest-content"
   ```

4. Apply the updated config to the node:
   ```bash
   export TALOSCONFIG=$(pwd)/gen/talosconfig
   talosctl apply-config --insecure --nodes <node-ip> --file gen/talos-controlplane-1.yaml
   ```

### Remove a Manifest

1. Delete the manifest file:
   ```bash
   rm manifests/talos-controlplane-1/unwanted-setting.yaml
   ```

2. Regenerate configuration:
   ```bash
   terraform apply
   ```

3. Apply the updated config to the node

## Best Practices

### Do's ✅
- Use manifests for **node-specific overrides**
- Keep manifests **small and focused** (one concern per file)
- Use **clear naming** (`networking.yaml`, `kernel-params.yaml`, etc.)
- Document **why** a manifest is needed (add comments in YAML)
- Test changes on non-production nodes first

### Don'ts ❌
- Don't duplicate the base machine config in manifests
- Don't mix multiple concerns in one manifest file
- Don't modify manifests for **cluster-level changes** (use Terraform instead)
- Don't rely on manifests for critical config (document in Terraform for clarity)

## Common Patterns

### Pattern 1: Per-Node Networking

**Use case:** Each control plane node on a different subnet

```
manifests/
├── talos-controlplane-1/
│   └── networking.yaml      # eth0: 10.0.1.10/24
├── talos-controlplane-2/
│   └── networking.yaml      # eth0: 10.0.2.10/24
└── talos-controlplane-3/
    └── networking.yaml      # eth0: 10.0.3.10/24
```

### Pattern 2: Production-Specific Overrides

**Use case:** Prod nodes need kernel tuning

```
manifests/
├── talos-cp-prod-1/
│   ├── kernel-tuning.yaml
│   └── sysctls.yaml
└── talos-cp-staging-1/
    # No tuning - uses defaults
```

### Pattern 3: Hardware-Specific Configuration

**Use case:** Different storage or GPU settings per node

```
manifests/
├── talos-worker-gpu/
│   └── gpu-drivers.yaml
└── talos-worker-compute/
    └── cpu-tuning.yaml
```

## Troubleshooting

### Manifest Not Applied

**Problem:** Changes in manifest not appearing in generated config

**Solution:**
1. Verify file path: `manifests/<node-name>/*.yaml`
2. Verify YAML syntax: `yamllint manifests/...`
3. Regenerate: `terraform apply`
4. Check output: `cat gen/<node-name>.yaml | tail -20`

### Configuration Conflicts

**Problem:** Manifest values conflict with base config

**Solution:**
- Manifests are appended after base config, so later values may override earlier ones
- Check generated file to see final merged state
- Adjust manifest content or base Terraform config as needed

### Node Won't Apply Configuration

**Problem:** `talosctl apply-config` fails after manifest change

**Solution:**
1. Verify manifest YAML is valid
2. Check node is in maintenance mode (Proxmox console)
3. Check Talos API version compatibility
4. Review node logs: `talosctl logs -k kubelet`

## Integration with Terraform

Terraform automatically:
- Discovers manifest files for each control plane node
- Concatenates manifests in alphabetical order
- Appends to the generated machine configuration
- Saves final config to `../gen/<node-name>.yaml`

If you need to change how manifests are processed, edit `talos.tf`:
```terraform
# See lines 36-47 in talos.tf
controlplane_manifests = {
  for node in var.control_plane : node.name => try(
    [for file in fileset("${local.manifests_base_dir}/${node.name}", "*.yaml") : file],
    []
  )
}
```
